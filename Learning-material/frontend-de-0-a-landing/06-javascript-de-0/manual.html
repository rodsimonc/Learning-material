JavaScript de 0

HTML da la estructura, CSS el estilo, y JavaScript el comportamiento: lo que hace que una página reaccione, cambie y responda. Este librito te enseña el lenguaje desde cero, con todo lo que necesitás para darle vida a una página. Es el más largo del track, y con razón: acá empezás a programar de verdad.

Cómo estudiarlo

Abrí las DevTools (F12) y andá a la pestaña "Console". Ahí podés escribir JavaScript y ver el resultado al instante, sin crear archivos. Probá cada ejemplo ahí. Flechas ← → para navegar.

Capítulo 1

Qué es JavaScript y dónde corre

JavaScript es el lenguaje de programación de la web. Corre dentro del navegador y puede reaccionar a lo que hace el usuario, cambiar la página, pedir datos a un servidor y mucho más. Es lo que convierte una página estática en una aplicación.

Tu primer código: la consola

No hace falta crear archivos para empezar. La consola del navegador ejecuta JavaScript directamente. Abrí las DevTools, andá a "Console", escribí esto y apretá enter:

consola
console.log("Hola desde JavaScript");

console.log() imprime algo en la consola. Es tu herramienta número uno para ver qué está pasando en tu código. La vas a usar constantemente.

Poner JS en una página

Como viste en el librito 1, el JS va en su archivo y se enlaza al final del <body>:

html
<script src="script.js"></script>
La consola es tu laboratorio

Todo lo de este librito lo podés probar en la consola sin crear nada. Escribí, apretá enter, vé el resultado. Es la forma más rápida de aprender el lenguaje.

Capítulo 2

Variables y tipos de datos

Una variable es una caja con nombre donde guardás un valor para usarlo después. Es el concepto más básico de la programación.

Declarar variables: let y const

javascript
let edad = 34;          // let: puede cambiar después
const nombre = "Carlos"; // const: no cambia (constante)

edad = 35;              // válido
nombre = "otro";        // ERROR: const no se puede reasignar
Regla práctica

Usá const por defecto, y let solo cuando sepas que el valor va a cambiar. Así tu código es más seguro: const te avisa si cambiás algo por accidente. Evitá var, que es la forma vieja con comportamientos confusos.

Los tipos de datos

javascript
let texto = "hola";        // string (texto, entre comillas)
let numero = 42;           // number (enteros y decimales)
let activo = true;         // boolean (true o false)
let nada = null;           // null (vacío a propósito)
let sinValor;              // undefined (sin asignar)
let lista = [1, 2, 3];     // array (lista de valores)
let persona = { edad: 34 };// object (datos con nombre)

Trabajar con texto (strings)

javascript
let nombre = "Carlos";
let saludo = "Hola, " + nombre;        // concatenar con +
let saludo2 = `Hola, ${nombre}`;       // template string (más limpio)
console.log(nombre.length);            // 6 (largo del texto)
console.log(nombre.toUpperCase());     // "CARLOS"

Las template strings (con acentos graves ` y ${}) son la forma moderna de armar texto con variables adentro. Muy cómodas.

Capítulo 3

Operadores y comparaciones

Los operadores hacen cosas con los valores: sumarlos, compararlos, combinarlos. Son la mecánica básica de cualquier lógica.

Aritméticos

javascript
10 + 3   // 13   suma
10 - 3   // 7    resta
10 * 3   // 30   multiplicación
10 / 3   // 3.33 división
10 % 3   // 1    resto (módulo): lo que sobra de dividir

Comparaciones

javascript
5 === 5    // true   igual (valor Y tipo)
5 === "5"  // false  distinto tipo
5 !== 3    // true   distinto
5 > 3      // true   mayor
5 <= 5     // true   menor o igual
Usá siempre === (tres iguales)

Hay == (dos iguales) que compara sin mirar el tipo y causa bugs raros (5 == "5" da true). Usá siempre === y !==, que comparan valor y tipo. Es una de las reglas de oro de JavaScript.

Lógicos

javascript
true && false   // false   Y: las dos tienen que ser true
true || false   // true    O: alcanza con una
!true           // false   NO: invierte

Estos combinan condiciones: "si es mayor de edad y tiene entrada", "si es finde o feriado". Son la base de las decisiones del próximo capítulo.

Capítulo 4

Condicionales: tomar decisiones

Un programa que siempre hace lo mismo no sirve de mucho. Los condicionales le dejan decidir: "si pasa esto, hacé aquello".

if / else

javascript
let edad = 20;

if (edad >= 18) {
  console.log("Puede pasar");
} else {
  console.log("Es menor");
}

if / else if / else

javascript
let nota = 7;

if (nota >= 9) {
  console.log("Excelente");
} else if (nota >= 6) {
  console.log("Aprobado");
} else {
  console.log("Desaprobado");
}

El operador ternario: un if corto

Para decisiones simples que asignan un valor, hay una forma compacta:

javascript
let edad = 20;
let mensaje = edad >= 18 ? "Puede pasar" : "Es menor";
//            condición    ? si es true    : si es false

Se lee: "¿edad mayor o igual a 18? Si sí, esto; si no, aquello". Muy usado para valores rápidos.

Capítulo 5

Funciones: empaquetar código

Una función es un bloque de código con nombre que podés ejecutar cuando quieras, cuantas veces quieras. Es la herramienta para no repetirte y para organizar la lógica.

Declarar y usar

javascript
function saludar(nombre) {
  return "Hola, " + nombre;
}

let mensaje = saludar("Carlos");   // "Hola, Carlos"
console.log(mensaje);
  • Parámetros (nombre): los datos que la función recibe.
  • return: el valor que devuelve. Sin return, la función no devuelve nada útil.

Arrow functions: la forma moderna

Hay una sintaxis más corta, muy usada hoy, sobre todo para funciones chicas:

javascript
const saludar = (nombre) => {
  return "Hola, " + nombre;
};

// versión ultra corta (si es una sola línea, return implícito):
const doble = (n) => n * 2;
console.log(doble(5));   // 10

Las dos formas hacen lo mismo. Vas a ver las arrow functions por todos lados, especialmente al trabajar con arrays y eventos.

Por qué importan

Las funciones son el corazón de programar: dividís un problema grande en piezas chicas con nombre. "Calcular el total", "validar el email", "mostrar el mensaje": cada una, una función.

Capítulo 6

Arrays: listas de valores

Un array es una lista ordenada de valores. Productos, usuarios, tareas: cualquier colección de cosas es un array. Y tiene métodos potentísimos para trabajarla.

Crear y acceder

javascript
let frutas = ["manzana", "pera", "uva"];

console.log(frutas[0]);      // "manzana" (empieza en 0)
console.log(frutas.length);  // 3
frutas.push("banana");       // agregar al final
console.log(frutas);         // ["manzana","pera","uva","banana"]
Cuidado: empieza en 0

El primer elemento es el [0], no el [1]. Es la fuente de bugs número uno de todo principiante. El tercer elemento es [2].

Los métodos que lo cambian todo

Tres métodos que vas a usar el resto de tu vida como dev. Todos reciben una función que se aplica a cada elemento.

javascript
let numeros = [1, 2, 3, 4];

// forEach: hacer algo con cada uno
numeros.forEach((n) => console.log(n));

// map: transformar cada uno en algo nuevo (devuelve otro array)
let dobles = numeros.map((n) => n * 2);   // [2, 4, 6, 8]

// filter: quedarse con los que cumplen una condición
let pares = numeros.filter((n) => n % 2 === 0);   // [2, 4]

map y filter son la base del frontend moderno: transformar una lista de datos en una lista de elementos HTML, o filtrar productos por categoría, se hacen así.

Capítulo 7

Objetos: datos con nombre

Si un array es una lista, un objeto es una ficha: agrupa datos relacionados bajo nombres. Un usuario tiene nombre, email y edad; eso es un objeto.

Crear y acceder

javascript
let usuario = {
  nombre: "Carlos",
  edad: 34,
  activo: true
};

console.log(usuario.nombre);   // "Carlos" (con punto)
usuario.edad = 35;             // modificar una propiedad
usuario.ciudad = "Mar del Plata"; // agregar una nueva

Arrays de objetos: el patrón estrella

La combinación más común en frontend: una lista de fichas. Así llegan los datos de una API, así se guardan los productos de una tienda.

javascript
let productos = [
  { nombre: "Teclado", precio: 25000 },
  { nombre: "Mouse", precio: 12000 },
  { nombre: "Monitor", precio: 90000 }
];

// combinando con lo anterior:
let baratos = productos.filter((p) => p.precio < 30000);
let nombres = productos.map((p) => p.nombre);
console.log(nombres);   // ["Teclado", "Mouse", "Monitor"]
Todo junto

Arrays de objetos + map/filter es el 80% del manejo de datos en frontend. Cuando en el DOM (próximo librito) generes una tarjeta por cada producto, vas a usar exactamente esto.

Capítulo 8

Bucles: repetir

Cuando necesitás hacer algo varias veces (recorrer una lista, repetir una acción), usás un bucle. JavaScript tiene varias formas; estas son las que importan.

for...of: recorrer una lista

La forma más clara de recorrer un array elemento por elemento:

javascript
let frutas = ["manzana", "pera", "uva"];

for (const fruta of frutas) {
  console.log(fruta);   // imprime cada una
}

for clásico: cuando necesitás el índice

javascript
for (let i = 0; i < 3; i++) {
  console.log("Vuelta número " + i);
}
// arranca en 0, sigue mientras i < 3, suma 1 cada vez

while: mientras se cumpla algo

javascript
let contador = 3;
while (contador > 0) {
  console.log(contador);
  contador--;   // resta 1, si no, sería infinito
}
for...of o los métodos de array

En la práctica, para recorrer arrays vas a usar mucho for...of o directamente forEach/map del capítulo de arrays. El for clásico queda para cuando necesitás controlar el índice o repetir un número exacto de veces.

Capítulo 9

La consola y los errores

Programar es, en buena parte, encontrar y arreglar errores. La consola es tu mejor aliada para eso. Aprender a leerla te ahorra horas.

console.log para espiar

Cuando algo no funciona, la técnica más simple y efectiva es imprimir valores para ver qué está pasando:

javascript
function calcularTotal(precio, cantidad) {
  console.log("precio:", precio, "cantidad:", cantidad);  // ¿qué llega?
  return precio * cantidad;
}

Leer un error

Cuando el código falla, la consola muestra un error en rojo. No te asustes: casi siempre te dice qué y dónde. Un ejemplo típico:

consola
Uncaught TypeError: Cannot read properties of undefined (reading 'nombre')
    at script.js:12

Eso dice: "intentaste leer .nombre de algo que es undefined, en la línea 12 de script.js". Vas a la línea 12 y revisás por qué esa variable está vacía. La mayoría de los errores se resuelven leyendo el mensaje y yendo a la línea que indica.

Errores comunes al empezar

  • Usar una variable mal escrita (mayúsculas cuentan: Nombre ≠ nombre).
  • Olvidar que los arrays empiezan en 0.
  • Usar = (asignar) cuando querías === (comparar).
  • Olvidar el return en una función.
El error es información

Un error en rojo no es un fracaso, es el navegador diciéndote exactamente qué pasó y dónde. Leerlo con calma es la habilidad que más rápido te hace mejorar.
