HTML: estructura y semántica

HTML es el esqueleto de toda página: define qué contenido hay y cómo se organiza. Este librito te enseña todas las etiquetas que vas a usar de verdad, con ejemplos que podés copiar y abrir en tu navegador. Al terminar vas a poder maquetar el contenido de cualquier página, listo para estilarlo en el próximo librito.

Cómo estudiarlo

Tené VS Code abierto y replicá cada ejemplo en tu index.html. HTML se aprende escribiéndolo y viéndolo en el navegador. Cada capítulo agrega etiquetas nuevas a tu repertorio.

Cómo moverte

Índice a la izquierda, o flechas ← →. El libro recuerda dónde quedaste.

Capítulo 1

Anatomía de una etiqueta

Todo en HTML se construye con etiquetas (o elementos). Entender su forma es entender el 90% del lenguaje: el resto es aprender qué etiquetas existen y para qué sirven.

La forma básica

Una etiqueta envuelve contenido con una apertura y un cierre. El cierre lleva una barra:

html
<p>Esto es un párrafo.</p>
 ▲                    ▲
 apertura            cierre (con /)

El navegador ve <p> y entiende "acá empieza un párrafo"; ve </p> y entiende "acá termina". Lo del medio es el contenido.

Atributos: información extra

Las etiquetas pueden llevar atributos en la apertura, que dan información adicional. Un atributo es un par nombre-valor:

html
<a href="https://ejemplo.com">Ir al sitio</a>
    ▲    ▲
  nombre  valor (entre comillas)

Acá href es el atributo que dice a dónde lleva el enlace. Cada tipo de etiqueta acepta ciertos atributos; los vas a ir conociendo.

Etiquetas que no llevan cierre

Algunas etiquetas no envuelven contenido, así que no tienen cierre. Se llaman vacías. La imagen es la más común:

html
<img src="foto.jpg" alt="Una foto">
<br>    <!-- un salto de línea -->
<hr>    <!-- una línea divisoria -->

Anidar: etiquetas dentro de etiquetas

Las etiquetas se meten unas dentro de otras, formando una jerarquía. Lo importante: se cierran en el orden inverso al que se abrieron, como paréntesis.

html
<p>Un párrafo con una <strong>palabra importante</strong> adentro.</p>
Error clásico

Cerrar en el orden equivocado: <p><strong>texto</p></strong> está mal. La etiqueta que se abre última se cierra primera. Anidá bien y te ahorrás bugs raros de estilo.

Comentarios

Podés dejar notas en el código que el navegador ignora, con <!-- ... -->. Útiles para explicar o para desactivar algo temporalmente.

Capítulo 2

La estructura de un documento HTML

Toda página arranca con el mismo esqueleto. No lo escribís de cero cada vez, pero conviene entender qué hace cada parte, porque ahí se configuran cosas importantes.

El esqueleto completo

index.html
<!DOCTYPE html>
<html lang="es">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Título de la pestaña</title>
  </head>
  <body>
    <!-- todo el contenido visible va acá -->
    <h1>Hola</h1>
  </body>
</html>

Qué hace cada parte

PartePara qué
<!DOCTYPE html>Le dice al navegador que use HTML moderno.
<html lang="es">La raíz de la página. lang declara el idioma (ayuda a buscadores y lectores de pantalla).
<head>Información sobre la página que no se ve en el cuerpo.
<body>Todo el contenido visible.

Las metaetiquetas clave del head

  • <meta charset="UTF-8">: la codificación de caracteres. Sin esto, los acentos y la ñ pueden verse mal.
  • <meta name="viewport" ...>: esencial para que la página se vea bien en el celular. La vas a entender a fondo en el librito de responsive, pero va siempre.
  • <title>: el texto de la pestaña del navegador y lo que muestran los buscadores.
Atajo útil

En VS Code, en un archivo .html vacío, escribí ! y apretá Tab: te genera todo este esqueleto solo. Igual conviene entender qué genera.

Capítulo 3

Texto: encabezados, párrafos y listas

El contenido de casi cualquier página es, ante todo, texto. Estas son las etiquetas para estructurarlo.

Encabezados: del h1 al h6

Los encabezados organizan la página en una jerarquía, como los títulos de un documento. Hay seis niveles:

html
<h1>Título principal de la página</h1>
<h2>Una sección</h2>
<h3>Una subsección</h3>
Regla importante

Un solo <h1> por página (el título principal), y no te saltés niveles (no pases de h2 a h4). Esta jerarquía la usan los buscadores y los lectores de pantalla para entender la página. No elijas el nivel por el tamaño; para eso está el CSS.

Párrafos y saltos

html
<p>Un párrafo de texto. El navegador ignora los saltos de línea
que escribas acá adentro; para separar párrafos usás etiquetas <p>.</p>
<p>Otro párrafo.</p>

Énfasis

html
<strong>importante</strong>   <!-- negrita con peso semántico -->
<em>énfasis</em>             <!-- cursiva con peso semántico -->

Existen <b> e <i> que solo cambian la apariencia, pero <strong> y <em> además comunican importancia, que es lo que suele querer decirse.

Listas

Dos tipos: sin orden (con viñetas) y ordenadas (con números). Ambas usan <li> (list item) para cada elemento.

html
<ul>                    <!-- unordered list -->
  <li>Manzanas</li>
  <li>Peras</li>
</ul>

<ol>                    <!-- ordered list -->
  <li>Primero esto</li>
  <li>Después esto</li>
</ol>

Las listas se usan más de lo que parece: un menú de navegación es, por debajo, una lista de enlaces.

Capítulo 4

Enlaces: lo que hace a la web una web

El enlace es la etiqueta que conecta páginas entre sí. Sin él no habría web. Se hace con <a> (de anchor) y su atributo href.

La forma básica

html
<a href="https://ejemplo.com">Visitá el sitio</a>

El href dice a dónde va; el texto entre las etiquetas es lo que ve y clickea el usuario.

Tipos de destino

DestinoEjemplo
Otro sitio (absoluto)href="https://otrositio.com"
Otra página tuya (relativo)href="contacto.html"
Una sección de la misma páginahref="#precios" (va al elemento con id="precios")
Un emailhref="mailto:hola@ejemplo.com"
Un teléfonohref="tel:+5491100000000"

Abrir en otra pestaña

html
<a href="https://otro.com" target="_blank" rel="noopener">Abrir aparte</a>

target="_blank" abre el enlace en una pestaña nueva. El rel="noopener" es una buena práctica de seguridad que conviene agregar siempre que uses _blank.

Enlaces internos y anclas

El truco de href="#seccion" es clave en las landing pages: un menú arriba que lleva a cada sección de la misma página con un scroll suave. Lo vas a usar en el proyecto.

Capítulo 5

Imágenes y multimedia

Las imágenes dan vida a una página. La etiqueta es <img>, y tiene dos atributos que siempre van juntos.

La imagen

html
<img src="productos/teclado.jpg" alt="Teclado mecánico negro">
  • src: la ruta a la imagen (dónde está el archivo).
  • alt: un texto que describe la imagen. No es opcional.
El alt no se saltea

El alt cumple tres funciones: lo lee el lector de pantalla para una persona ciega, se muestra si la imagen no carga, y lo usan los buscadores. Describí lo que muestra la imagen. Si es puramente decorativa, poné alt="" vacío, pero el atributo va igual.

Imagen con epígrafe

Cuando una imagen necesita un pie de foto, se usa <figure> con <figcaption>:

html
<figure>
  <img src="grafico.png" alt="Ventas por mes en 2026">
  <figcaption>Ventas mensuales del último año.</figcaption>
</figure>

Formatos de imagen

FormatoCuándo
JPGFotos. Buen equilibrio peso/calidad.
PNGCuando necesitás fondo transparente o bordes nítidos.
SVGLogos e íconos. Es vectorial: no pierde calidad al escalar.
WebPFormato moderno, más liviano. Ideal para la web hoy.

Video

html
<video src="demo.mp4" controls width="600"></video>

controls muestra los botones de reproducción. El peso de las imágenes y videos es clave para la velocidad de la página, tema del librito de rendimiento.

Capítulo 6

Formularios: capturar datos

Los formularios son cómo el usuario te manda información: un login, un registro, un campo de contacto. Acá va la estructura HTML; la validación con JavaScript tiene su propio librito.

La estructura

html
<form>
  <label for="email">Tu email</label>
  <input type="email" id="email" name="email" placeholder="hola@ejemplo.com">

  <label for="msg">Mensaje</label>
  <textarea id="msg" name="mensaje"></textarea>

  <button type="submit">Enviar</button>
</form>

El label y el for

Cada campo debería tener su <label>. El atributo for del label debe coincidir con el id del input. Así, al tocar la etiqueta se activa el campo, y el lector de pantalla sabe qué pide cada casilla. Es accesibilidad básica que no cuesta nada.

Los tipos de input

El atributo type cambia el comportamiento del campo:

typePara
textTexto común.
emailEmails (valida el formato, en móvil muestra el teclado con @).
passwordContraseñas (oculta lo que se escribe).
numberNúmeros.
checkbox / radioCasillas y opciones.
dateSelector de fecha.
Elegir el type correcto rinde

Usar type="email" en vez de text te da validación básica gratis y, en el celular, el teclado adecuado. Elegir bien el tipo es la forma más barata de mejorar un formulario.

Capítulo 7

HTML semántico: etiquetas con significado

Podrías construir toda una página con <div> (una caja genérica sin significado). Pero HTML tiene etiquetas que dicen qué es cada parte, y usarlas es lo que separa un HTML profesional de uno amateur.

Las etiquetas de estructura

En vez de cajas anónimas, nombrás cada región de la página por lo que es:

html
<body>
  <header>      <!-- encabezado: logo, navegación -->
    <nav></nav>   <!-- el menú de navegación -->
  </header>

  <main>        <!-- el contenido principal, único por página -->
    <section></section>   <!-- una sección temática -->
    <article></article>   <!-- contenido autónomo (un post, una tarjeta) -->
  </main>

  <aside></aside>   <!-- contenido lateral, secundario -->

  <footer></footer>  <!-- pie: contacto, enlaces, copyright -->
</body>

Semántica vs div

Comparalos. El de la izquierda no dice nada; el de la derecha se lee solo:

antes (todo div) vs después (semántico)
<div class="header">        <header>
  <div class="nav">           <nav>
<div class="main">          <main>
<div class="footer">        <footer>

El <div> sigue siendo útil para agrupar cosas cuando no hay una etiqueta semántica que aplique. Pero primero buscá la semántica; el div es el último recurso.

Capítulo 8

Por qué la semántica importa

Usar la etiqueta correcta no es un capricho de purista. Tiene tres beneficios concretos que se cobran solos, sin trabajo extra.

Accesibilidad

Las personas que usan lectores de pantalla navegan por la estructura semántica: "saltar al contenido principal" funciona porque existe un <main>; "listar los encabezados" funciona porque usaste <h1> a <h3> bien. Con puros <div>, esa navegación se rompe. Tiene su propio librito (Accesibilidad y SEO), pero empieza acá, en el HTML.

SEO

Los buscadores leen tu HTML para entender de qué trata la página. Una estructura semántica clara, con encabezados bien jerarquizados, les facilita indexarte bien. HTML prolijo es SEO gratis.

Mantenibilidad

Un HTML semántico se lee como un documento: cualquiera que lo abra entiende la estructura de un vistazo. Cuando vuelvas a tu propio código en tres meses, te vas a agradecer no haber puesto veinte <div> anónimos.

La regla práctica

Antes de escribir un <div>, preguntate si existe una etiqueta que describa qué es ese contenido. Si es el encabezado, header; si es navegación, nav; si es el pie, footer. El div queda para cuando de verdad no hay nada mejor.

Cierre

Buenas prácticas, cheatsheet y glosario

Buenas prácticas

  • Un <h1> por página; encabezados sin saltar niveles.
  • alt en toda imagen; label en todo campo de formulario.
  • Semántica antes que <div>.
  • Indentá el código (sangría) para que la anidación se lea. VS Code te ayuda.
  • El HTML define qué es el contenido, no cómo se ve. El "cómo se ve" es del CSS, próximo librito.
