Responsive design

La mayoría de la gente entra a la web desde el celular. Una página que solo se ve bien en la compu está media hecha. Responsive design es hacer que una misma página se vea bien en cualquier tamaño de pantalla, del teléfono al monitor grande. Este librito te enseña a lograrlo.

Cómo estudiarlo

Probá cada ejemplo y achicá la ventana del navegador para ver los cambios. Las DevTools tienen un modo de dispositivo (ícono de celular) para simular pantallas. Flechas ← → para navegar.

Capítulo 1

Qué significa responsive

Una página responsive se adapta al tamaño de la pantalla: reacomoda columnas, ajusta tamaños de texto, y reorganiza el contenido para que siempre se vea y se use bien.

La etiqueta que lo habilita todo

Antes que nada, en el <head> tiene que estar esta meta (ya la viste en el librito de HTML). Sin ella, el celular "miente" sobre su tamaño y tu diseño responsive no funciona:

html · imprescindible
<meta name="viewport" content="width=device-width, initial-scale=1">

Le dice al navegador "usá el ancho real del dispositivo". Es el primer paso, no negociable.

Mobile-first: la mentalidad correcta

La forma recomendada de trabajar es mobile-first: diseñás primero para la pantalla chica, y después vas agregando lo que cambia en pantallas más grandes. Es más fácil agrandar un diseño simple que apretar uno complejo.

Por qué mobile-first

La pantalla chica te obliga a priorizar: qué es lo esencial. Cuando eso funciona, agregar espacio y columnas para pantallas grandes es sencillo. Al revés, achicar un diseño de escritorio siempre termina en desastre.

Capítulo 2

Media queries: estilos según el ancho

La media query es la herramienta central del responsive: un bloque de CSS que se aplica solo cuando la pantalla cumple una condición, como "tener al menos 768px de ancho".

La sintaxis

css · mobile-first
/* estilos base: para celular (se aplican siempre) */
.columnas {
  display: grid;
  grid-template-columns: 1fr;   /* una columna en el celu */
}

/* a partir de 768px de ancho, cambia a dos columnas */
@media (min-width: 768px) {
  .columnas {
    grid-template-columns: 1fr 1fr;
  }
}

Fijate el enfoque mobile-first: el estilo base es para móvil, y con min-width vas agregando lo que cambia hacia arriba. El navegador aplica el bloque solo cuando la pantalla mide 768px o más.

Los breakpoints típicos

Los "puntos de quiebre" son los anchos donde cambiás el diseño. No hay valores sagrados, pero estos son comunes:

BreakpointAproximadamente
~480pxCelulares grandes
~768pxTablets
~1024pxNotebooks
~1280px+Monitores grandes
Poné el breakpoint donde se rompe

El mejor breakpoint no sale de una tabla: sale de achicar la ventana hasta que el diseño se ve mal, y poner el corte ahí. Diseñá para el contenido, no para dispositivos concretos.

Capítulo 3

Layouts que se adaptan solos

La mejor media query es la que no tenés que escribir. Con las técnicas que ya viste de Flexbox y Grid, muchos layouts se adaptan sin una sola media query. Menos código, menos que mantener.

Grid que se acomoda solo

La receta del librito anterior, ahora en su contexto: una galería que pasa de muchas columnas a una sin media queries.

css
.galeria {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(250px, 1fr));
  gap: 20px;
}
/* en pantalla ancha: varias columnas. en el celu: una. Solo. */

Flexbox con wrap

css
.tarjetas {
  display: flex;
  flex-wrap: wrap;
  gap: 20px;
}
.tarjetas > * { flex: 1 1 250px; }  /* bajan de línea cuando no entran */

Anchos máximos y contenido centrado

En pantallas muy anchas, el texto a todo el ancho es incómodo de leer. La solución es un contenedor con ancho máximo, centrado:

css
.contenido {
  max-width: 1100px;   /* no crece más de esto */
  margin: 0 auto;      /* centrado */
  padding: 0 20px;     /* aire a los lados en pantallas chicas */
}
La estrategia en capas

Primero, layouts fluidos (auto-fit, flex-wrap, max-width) que se adaptan solos. Después, media queries solo para los cambios que lo fluido no resuelve, como reorganizar la navegación. Menos media queries, más robusto.

Capítulo 4

Imágenes y texto que se adaptan

Dos detalles que rompen el responsive de los principiantes: imágenes que se desbordan y texto que no escala. Los dos se arreglan fácil.

Imágenes que nunca se desbordan

Una regla que va casi siempre: que ninguna imagen sea más ancha que su contenedor.

css
img {
  max-width: 100%;   /* nunca más ancha que su contenedor */
  height: auto;      /* mantiene la proporción */
}

Sin esto, una foto grande se sale de la pantalla en el celular y aparece scroll horizontal, el síntoma clásico de un responsive roto.

Texto que escala con la pantalla

La función clamp() te deja definir un tamaño que crece con la pantalla pero con topes:

css
h1 {
  font-size: clamp(1.8rem, 5vw, 3.5rem);
  /*          mínimo | ideal | máximo */
}

Léelo así: "nunca menos de 1.8rem, nunca más de 3.5rem, y en el medio, el 5% del ancho de la ventana". El título se agranda solo en pantallas grandes y se achica en el celular, sin media queries.

El enemigo: el scroll horizontal

Si en el celular tu página se mueve de costado, algo se desborda: casi siempre una imagen sin max-width, un ancho fijo en px muy grande, o un texto largo sin cortar. Achicá la ventana y buscá qué se sale.

Capítulo 5

Una sección responsive de punta a punta

Juntemos todo en una sección real: en el celular es una columna; en pantalla ancha, dos. Con el mínimo de media queries.

html
<section class="hero">
  <div class="hero-texto">
    <h1>Tu producto, más simple</h1>
    <p>Una frase que lo explica.</p>
    <a class="cta" href="#">Empezar</a>
  </div>
  <img class="hero-img" src="producto.png" alt="El producto">
</section>
css
/* base: móvil, una columna */
.hero {
  display: grid;
  gap: 24px;
  padding: 40px 20px;
  max-width: 1100px;
  margin: 0 auto;
}
.hero h1 { font-size: clamp(2rem, 6vw, 3.5rem); }
.hero-img { max-width: 100%; height: auto; }

/* desde 768px: dos columnas, texto e imagen lado a lado */
@media (min-width: 768px) {
  .hero {
    grid-template-columns: 1fr 1fr;
    align-items: center;
  }
}

En el celular, el texto va arriba y la imagen abajo (una columna). Desde 768px, quedan lado a lado. El título escala solo con clamp(). Una sola media query para todo el cambio.

Cierre

Cómo probarlo, y cheatsheet

Probar en distintos tamaños

No necesitás mil dispositivos. En el navegador, abrí las DevTools (F12) y activá el modo dispositivo (ícono de celular/tablet). Ahí elegís tamaños y ves tu página como en cada uno. Achicá y agrandá la ventana también: si algo se rompe, lo ves al instante.

Checklist de una página responsive

  • Está la meta viewport en el <head>.
  • Ninguna imagen se desborda (img { max-width: 100%; }).
  • No hay scroll horizontal en el celular.
  • El texto se lee cómodo sin hacer zoom.
  • Los botones y enlaces son fáciles de tocar con el dedo (no muy chicos ni pegados).
  • El contenido tiene un ancho máximo en pantallas grandes.

Cheatsheet

Lo que te llevás

Sabés hacer que una página se vea bien en cualquier pantalla: mobile-first, media queries, layouts fluidos, e imágenes y texto que escalan. Ya tenés todo el CSS que necesitás para construir. Ahora viene el tercer lenguaje: JavaScript, para darle comportamiento.
