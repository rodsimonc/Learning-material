Cómo funciona la web

Antes de escribir una sola línea de código conviene entender qué pasa cuando abrís una página. Este primer librito te da el mapa: cómo viaja una página hasta tu pantalla, qué hace el navegador con ella, y cuáles son los tres lenguajes que vas a aprender en todo el track. Sin esto, lo demás son pasos sueltos; con esto, cobra sentido.

Dónde estás en el track

Este es el punto de partida de Frontend, de 0 a una landing page. Acá no escribís casi código todavía: armás el modelo mental y preparás tu entorno. Desde el librito 2 empezás a maquetar.

Cómo moverte

Capítulo 1

Qué pasa cuando abrís una página

Escribís una dirección, apretás enter, y en un segundo aparece una página. Debajo de esa magia hay una conversación simple entre dos partes: tu navegador que pide, y un servidor que responde.

Cliente y servidor

La web funciona con dos roles. El cliente es tu navegador: quien pide. El servidor es una computadora en algún lado que tiene la página guardada: quien responde. Vos pedís, el servidor contesta, y la conversación termina.

la conversación, simplificada
  Tu navegador                          Servidor
  (cliente)                             (en algún lado)
      │                                     │
      │   "dame la página miweb.com"        │
      │ ───────── request ────────────────▶ │
      │                                     │
      │   "acá está: este HTML"             │
      │ ◀──────── response ──────────────── │
      │                                     │
   la muestra

La dirección: qué es una URL

Cuando escribís https://miweb.com, esa es la URL: la dirección del recurso que querés. El navegador necesita saber a qué servidor pegarle, y para eso traduce ese nombre a una dirección numérica (una IP) a través del DNS, que funciona como la guía telefónica de internet. No hace falta que memorices esto ahora; solo que sepas que "el nombre lindo" se traduce a "dónde está de verdad".

HTTP: el idioma del pedido

Ese pedir y responder usa un protocolo llamado HTTP (con la S de seguro, HTTPS, cuando va cifrado, que es lo normal hoy). El navegador manda un request y el servidor devuelve un response con el contenido. Vas a escuchar mucho estos dos términos.

La idea en una línea

Abrir una página es tu navegador pidiéndole un archivo a un servidor, y el servidor mandándoselo. Todo lo demás es qué hace el navegador con ese archivo.

Capítulo 2

Qué hace el navegador con lo que recibe

El servidor te manda texto: un archivo HTML. El navegador es quien convierte ese texto en la página con colores, imágenes y botones que ves. Entender ese proceso te ayuda a saber por qué a veces las cosas no aparecen como esperás.

De texto a página

Cuando llega el HTML, el navegador lo lee de arriba a abajo y hace, en orden:

  1. Lee el HTML y arma una estructura interna de la página (qué elementos hay y cómo se anidan).
  2. Pide los archivos que el HTML menciona: las hojas de estilo (CSS), los scripts (JS), las imágenes, las fuentes. Cada uno es otro pedido al servidor.
  3. Aplica el CSS para darle forma y color a cada elemento.
  4. Ejecuta el JavaScript, que puede cambiar la página.
  5. Pinta el resultado en la pantalla.

Por eso una página puede aparecer primero sin estilos por una fracción de segundo: el HTML llegó antes que el CSS. Y por eso el orden en que cargás las cosas importa, algo que vas a ver más adelante.

Las DevTools: tu ventana al proceso

Todo navegador trae herramientas de desarrollador (las DevTools), que abrís con F12 o clic derecho, "Inspeccionar". Ahí ves el HTML real de cualquier página, los estilos aplicados, y los archivos que se pidieron. Es la herramienta que más vas a usar en todo el track, así que familiarizate desde ya: abrí cualquier sitio y mirá su estructura.

Probá esto

Abrí una página cualquiera, apretá F12 y andá a la pestaña "Elements" (o "Elementos"). Vas a ver el HTML de esa página. Pasá el mouse por las líneas y fijate cómo se resaltan las partes en la pantalla.

Capítulo 3

HTML, CSS y JavaScript: los tres roles

Toda página web se construye con tres lenguajes, y cada uno tiene un trabajo distinto. Entender la división es la base de todo el frontend. La analogía clásica es una casa.

La analogía de la casa

LenguajeRolEn la casa
HTMLLa estructura: qué contenido hayLas paredes, las puertas, las habitaciones
CSSEl estilo: cómo se veLa pintura, los muebles, la decoración
JavaScriptEl comportamiento: qué haceLa electricidad: las luces que se prenden, la puerta que se abre

Un vistazo a cada uno

No hace falta que entiendas el código todavía. Solo mirá que cada uno tiene una forma distinta y un propósito distinto.

HTML · estructura
<h1>Bienvenido</h1>
<button>Comprar</button>
CSS · estilo
button {
  background: teal;
  color: white;
}
JavaScript · comportamiento
button.addEventListener("click", () => {
  alert("¡Gracias por tu compra!");
});

El HTML pone el botón, el CSS lo pinta, y el JavaScript hace que al hacer clic pase algo. Los tres trabajan juntos sobre la misma página.

El orden de aprendizaje

Se aprenden en ese orden y por una razón: primero la estructura (HTML), después el estilo (CSS), y al final el comportamiento (JS). Este track sigue exactamente ese camino.

Capítulo 4

Preparar tu entorno

Para escribir frontend necesitás dos cosas, las dos gratis: un editor de código y un navegador. Nada más para empezar.

El editor: VS Code

Un editor de código es donde vas a escribir. El más usado hoy es Visual Studio Code (VS Code), gratis y liviano. Lo descargás de su sitio oficial y lo instalás como cualquier programa. Escribe con colores según el tipo de código, autocompleta, y avisa de errores.

Una extensión que ayuda: Live Server

Dentro de VS Code podés instalar extensiones. Una muy útil para empezar es Live Server: levanta tu página en el navegador y la recarga sola cada vez que guardás. Ves los cambios al instante, sin recargar a mano. Se instala desde la pestaña de extensiones buscando "Live Server".

El navegador

Cualquier navegador moderno sirve (Chrome, Firefox, Edge). Lo importante son sus DevTools, que ya viste. Muchos desarrolladores usan Chrome o Firefox por sus herramientas, pero para aprender da igual.

Lo mínimo para arrancar

VS Code + un navegador. Con eso ya podés construir cualquier cosa de este track. Las herramientas más avanzadas llegan cuando las necesites, no antes.

Capítulo 5

Tu primer archivo HTML

Momento de crear algo. Un archivo HTML es un archivo de texto con extensión .html que el navegador sabe interpretar. Vamos a hacer el clásico primer paso.

Crear y abrir

En VS Code, creá un archivo llamado index.html (ese nombre es especial: es la página principal por convención). Escribí esto adentro:

index.html
<!DOCTYPE html>
<html lang="es">
  <head>
    <meta charset="UTF-8">
    <title>Mi primera página</title>
  </head>
  <body>
    <h1>Hola, mundo</h1>
    <p>Esta es mi primera página web.</p>
  </body>
</html>

Guardá el archivo y abrilo en el navegador (doble clic, o con Live Server). Vas a ver "Hola, mundo" grande y un párrafo debajo. Acabás de hacer tu primera página.

Qué es cada parte, por encima

  • <!DOCTYPE html>: le dice al navegador "esto es HTML moderno".
  • <head>: información sobre la página que no se ve (el título de la pestaña, el idioma, la codificación).
  • <body>: el contenido que sí se ve.

El librito 2 se mete a fondo con cada etiqueta. Por ahora, lo importante es que creaste, guardaste y abriste una página real.

Capítulo 6

Cómo se conectan los tres

Una página real no es solo HTML: también tiene su CSS y su JS. La forma limpia de trabajar es tener cada lenguaje en su propio archivo y conectarlos desde el HTML.

Tres archivos, una página

La estructura típica de un proyecto chico:

carpeta del proyecto
mi-sitio/
  index.html      ← la estructura
  estilos.css     ← el estilo
  script.js       ← el comportamiento

Conectarlos desde el HTML

El HTML es el que llama a los otros dos. El CSS se enlaza en el <head>, y el JS al final del <body>:

index.html
<!DOCTYPE html>
<html lang="es">
  <head>
    <meta charset="UTF-8">
    <title>Mi sitio</title>
    <link rel="stylesheet" href="estilos.css">
  </head>
  <body>
    <h1>Hola</h1>
    <script src="script.js"></script>
  </body>
</html>

El <link> trae el CSS; el <script> trae el JS. Cuando el navegador lee el HTML, ve esas líneas y pide esos archivos, tal como viste en el capítulo 2.

Por qué el script va al final

Poner el <script> justo antes de cerrar el <body> asegura que el HTML ya esté cargado cuando el JS corre. Si lo ponés arriba, el JS podría intentar tocar elementos que todavía no existen. Es un detalle que evita errores comunes.
