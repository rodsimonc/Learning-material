Capítulo 1

Qué es programar

Programar es darle a una computadora una lista de instrucciones, en un orden preciso, para que haga algo por vos. Nada más místico que eso. La computadora no es inteligente en el sentido humano: es rapidísima y obediente. Hace exactamente lo que le decís, en el orden que se lo decís, sin adivinar lo que quisiste decir.

Una receta, pero para la máquina

Pensá en una receta de cocina: "poné agua, esperá a que hierva, agregá la pasta, esperá 10 minutos, colá". Es una secuencia de pasos, en orden, y cada paso es claro. Un programa es igual: una secuencia de instrucciones. La diferencia es que la computadora es literal al extremo. Si en la receta te salteás "esperá a que hierva", una persona lo deduce; la computadora no. Por eso programar exige precisión, y por eso al principio vas a cometer errores de detalle. Es normal, le pasa a todos, siempre.

Cómo piensa la computadora

Por dentro, la computadora solo entiende números (ceros y unos). Escribir en ese idioma sería imposible para nosotros, así que se inventaron los lenguajes de programación: idiomas intermedios, más parecidos al humano, que después se traducen a lo que la máquina entiende. Nosotros escribimos en el lenguaje, y un programa traductor se encarga del resto.

Por qué Python

Hay muchos lenguajes (Python, JavaScript, Java, C, y decenas más). Empezamos con Python por buenas razones: se lee casi como inglés simple, es limpio y perdona (no te obliga a detalles que distraen al principio), y es de los más usados del mundo, en páginas web, análisis de datos, inteligencia artificial y automatización. Lo que aprendas de programar con Python (la forma de pensar) te sirve para cualquier otro lenguaje después.

Lo que de verdad vas a aprender

Este libro enseña Python, sí, pero lo más importante que te llevás no es la sintaxis (esa se olvida y se vuelve a buscar mil veces, todos lo hacemos). Lo que queda es pensar como programador: descomponer un problema en pasos, y traducir esos pasos a instrucciones. Esa habilidad es la que vale, y es la misma en todos los lenguajes.

print es tu primera instrucción y la que más vas a usar mientras aprendés. Muestra en la consola lo que le pongas entre paréntesis. Simple, pero tiene más detalles útiles de los que parece.

Lo que acabás de ver

  • Varios valores: print acepta varias cosas separadas por comas, y las muestra con un espacio entre ellas. Podés mezclar texto y números.
  • sep: cambia lo que va entre los valores (por defecto, un espacio).
  • end: lo que va al final (por defecto, un salto de línea). Con end="", el siguiente print sigue en la misma línea.
  • \n y \t: son "secuencias de escape". \n es un salto de línea (una Enter), \t una tabulación. La barra invertida \ le avisa a Python que lo que sigue es especial.

Texto entre comillas

Fijate que el texto siempre va entre comillas: "Hola". Podés usar comillas dobles " o simples ', es lo mismo, pero elegí una y sé consistente. Los números NO llevan comillas: 3 es el número tres; "3" es el texto que contiene el carácter tres (y como vas a ver, no son la misma cosa).

Errores típicos con print

Los tres tropiezos del primer día: olvidarse de cerrar el paréntesis print("hola" (falta el )); olvidarse una comilla print("hola); y escribir Print con mayúscula (Python distingue mayúsculas de minúsculas, es print). Si algo no anda, revisá estos tres primero. Los mensajes de error de Python te señalan la línea; leelos, son tus amigos.

Capítulo 4

Comentarios y buen estilo

El código no lo lee solo la computadora: lo leés vos dentro de un mes, y otras personas. Escribir código claro, con comentarios donde hacen falta, es parte de programar bien desde el día uno. Un programa que anda pero no se entiende es una bomba de tiempo.

Comentarios

Un comentario es texto que Python ignora por completo: está ahí para los humanos. Se escribe con el símbolo #; todo lo que va después en esa línea es comentario.

comentarios
# Esto es un comentario: explica QUÉ o POR QUÉ, no lo obvio
precio = 8500  # precio de la pizza muzzarella

# Calculamos el total del pedido de 2 unidades
total = precio * 2

Buenos comentarios vs malos

Un comentario no debe repetir lo que el código ya dice. x = x + 1 # sumar 1 a x es inútil: se ve. El buen comentario explica el por qué, o aclara algo que no es obvio: # sumamos 1 porque las posiciones empiezan en 0. La regla: si el código es claro, no necesita comentario; el comentario es para lo que el código no puede decir por sí mismo.

Nombres que se entienden

La mejor forma de que el código se explique solo es con buenos nombres. Compará:

malo vs bueno
# malo: ¿qué es x? ¿qué es y?
x = 8500
y = 2
z = x * y

# bueno: se lee como una frase
precio_unitario = 8500
cantidad = 2
total = precio_unitario * cantidad

Los nombres en Python se escriben en minúsculas, y si tienen varias palabras, se separan con guión bajo: precio_unitario, total_con_iva. Este estilo se llama "snake_case" y es la convención de Python.

El código se lee más de lo que se escribe

Vas a escribir una línea una vez y leerla decenas de veces (vos y otros) mientras la corregís y ampliás. Por eso vale la pena que sea clara: buenos nombres, comentarios donde ayudan, y orden. No es perfeccionismo, es practicidad. El "yo del futuro" te lo va a agradecer.

Capítulo 5

Variables: guardar datos

Un programa trabaja con datos: precios, nombres, cantidades. Para guardarlos y usarlos después, se usan variables. Una variable es un nombre al que le asignás un valor. La imagen clásica: una caja con una etiqueta, donde guardás algo.

Crear una variable

asignación
precio = 1200
nombre = "Pizza"
cantidad = 3

El signo = es la asignación: "guardá el valor de la derecha en la variable de la izquierda". A partir de ahí, cada vez que escribas precio, Python usa 1200. Si mañana el precio cambia, lo modificás en un solo lugar y todo el programa se actualiza.

= no significa "es igual a"

Este es un quiebre mental importante. En matemática, = es igualdad. En programación, = es una acción: "guardá esto acá". Por eso precio = precio + 100 tiene sentido (no sería posible como igualdad matemática): significa "tomá el precio actual, sumale 100, y guardá el resultado de vuelta en precio". Para preguntar si dos cosas son iguales se usa == (doble), que vemos más adelante.

Los tipos de dato básicos

Cada valor tiene un tipo. Los cuatro fundamentales:

TipoQué esEjemplos

floatNúmero con decimales0.25, 3.14, 1.0

type() te dice el tipo de un valor. Es útil cuando algo no anda y sospechás que un dato no es lo que creías (un clásico: tener un número guardado como texto).

Reglas para los nombres

  • Pueden tener letras, números y guión bajo, pero no empezar con número.
  • Distinguen mayúsculas: precio y Precio son variables distintas.
  • No pueden ser palabras reservadas de Python (if, for, print, etc.).
  • Por convención: minúsculas y snake_case (precio_unitario).
Python no te obliga a declarar el tipo

En otros lenguajes tenés que decir "esta variable es un número". En Python no: le asignás un valor y Python deduce el tipo solo. Es más cómodo para empezar. La contra es que un error de tipo (multiplicar texto por texto) aparece recién al correr, no antes; por eso el type() es útil para chequear.

Capítulo 6

Números y operaciones

Los números son la base de casi todo cálculo. Python maneja enteros (int) y decimales (float), y trae todos los operadores matemáticos que necesitás, más un par que quizás no conocés.

Todos los operadores

print("suma:", 7 + 3)              # 10
print("resta:", 7 - 3)            # 4
print("multiplicacion:", 7 * 3)   # 21
print("division:", 7 / 3)         # 2.333... (siempre da float)
print("division entera:", 7 // 3) # 2 (descarta los decimales)
print("resto (modulo):", 7 % 3)   # 1 (lo que sobra de dividir)
print("potencia:", 2 ** 10)       # 1024 (2 elevado a 10)
salida real✓ salida real

multiplicacion: 21
division: 2.3333333333333335
division entera: 2

Dos que sorprenden: // y %

La división entera // te da cuántas veces entra un número en otro, sin decimales: 7 // 3 es 2 (el 3 entra 2 veces en el 7). El módulo % te da lo que sobra: 7 % 3 es 1. Parecen raros pero son utilísimos. El truco más común: numero % 2 == 0 te dice si un número es par (si el resto de dividir por 2 es cero).

Precedencia: el orden importa

precedencia
print("sin parentesis:", 2 + 3 * 4)     # 14 (primero 3*4, despues +2)
print("con parentesis:", (2 + 3) * 4)   # 20 (primero el parentesis)

Como en matemática: primero se resuelven multiplicaciones y divisiones, después sumas y restas. Y los paréntesis mandan sobre todo. En la duda, poné paréntesis: aclaran la intención y evitan errores.

Redondeo y decimales

redondear
print("redondear:", round(4356.789, 2))   # 4356.79 (a 2 decimales)
print("par?:", 10 % 2 == 0)                # True
Los decimales tienen truquitos

Habrás notado que 7 / 3 dio 2.3333333333333335 con un 5 raro al final. Los float guardan decimales con precisión limitada, así que a veces aparecen esas colas. Para mostrar, usá round() o el formato de los f-strings (próximo capítulo). Y ojo con el dinero: para plata exacta, en sistemas reales se evita el float (se usan enteros de centavos o tipos especiales), justamente por esto.

Capítulo 7

Texto: los strings a fondo

Casi todo programa maneja texto: nombres, mensajes, datos que llegan como texto. En Python el texto es el tipo str (string), y viene con un montón de herramientas para manipularlo. Este es un tema grande porque el texto está en todos lados.

Crear y medir

nombre = "Pizza Muzzarella"

print("mayusculas:", nombre.upper())
print("minusculas:", nombre.lower())

len() cuenta los caracteres (incluye espacios). Los métodos como .upper(), .lower(), .replace() se escriben con un punto después del texto, y devuelven un texto nuevo (no cambian el original: el texto en Python es "inmutable").

Acceder a partes: indexado y slicing

indexado y slicing
print("primera letra:", nombre[0])   # P (se cuenta desde 0)
print("ultimas 4:", nombre[-4:])     # ella (negativo cuenta desde el final)
print("primeras 5:", nombre[0:5])    # Pizza (de la 0 a la 5, sin incluir la 5)
salida real✓ salida real

Un texto es una secuencia de caracteres numerados desde 0. nombre[0] es el primero. Los negativos cuentan desde el final: nombre[-1] es el último. El "slicing" [inicio:fin] saca un pedazo (el fin no se incluye). Esto mismo vale para las listas, como vas a ver.

Dividir y unir

split y join

print("split:", partes)                    # ['carne', 'pollo', 'jamon']
print("unir:", " + ".join(partes))         # carne + pollo + jamon

.split() parte un texto en una lista; .join() hace lo inverso. .strip() saca espacios sobrantes de los bordes (clave al limpiar datos que escribe la gente).

La forma moderna y cómoda de meter valores dentro de un texto. Ponés una f antes de las comillas, y lo que va entre llaves {} se reemplaza por su valor.

Vas a usarlos todo el tiempo para armar mensajes con datos. Podés meter cualquier expresión entre las llaves ({precio*cant}), y darle formato después de dos puntos (:,.2f = separador de miles y 2 decimales). Es mucho más claro que andar concatenando con +.

Capítulo 8

Booleanos: verdadero o falso

Un booleano solo puede valer True (verdadero) o False (falso). Parece poca cosa, pero es la base de todas las decisiones de un programa: "¿hay stock?", "¿está pago?", "¿el número es par?". Todo eso son preguntas cuya respuesta es un booleano.

Las comparaciones dan booleanos

Cuando comparás dos valores, el resultado es True o False:

OperadorPreguntaEjemplo → resultado
==¿son iguales?5 == 5 → True
!=¿son distintos?5 != 3 → True
< >menor / mayor3 < 5 → True
<= >=menor-igual / mayor-igual5 >= 5 → True
Un = o dos ==

El error más común de principiante: usar = (asignar) donde va == (comparar). precio = 8500 guarda; precio == 8500 pregunta si son iguales y da True/False. Uno guarda, dos preguntan. Python casi siempre te avisa si los confundís, pero grabate la diferencia desde ahora.

Combinar condiciones: and, or, not

print("or:", pedido > stock or pagado)             # True (al menos una)
print("not:", not pagado)                           # False (invierte)
print("entre 18 y 65:", 18 <= 25 <= 65)             # True (encadenada)

  • and (y): verdadero solo si las dos condiciones lo son.
  • or (o): verdadero si al menos una lo es.
  • not (no): invierte, convierte True en False y viceversa.
  • Podés encadenar: 18 <= edad <= 65 pregunta si está en el rango, tal como lo escribirías en matemática.

Vacío es falso

En Python, el cero, el texto vacío y las listas vacías se consideran "falsos" cuando se los usa como condición. Esto es muy práctico: en vez de if len(lista) > 0: podés escribir if lista: ("si la lista tiene algo"). Se lee mejor y es la forma pythónica.

Capítulo 9

Convertir tipos y pedir datos al usuario

Los datos no siempre vienen en el tipo que necesitás. Un número que escribe el usuario llega como texto. Saber convertir entre tipos, y pedirle datos a quien usa el programa, es lo que hace tus programas interactivos.

Convertir de un tipo a otro

print("como texto:", str(1500) + " pesos")   # numero a texto para concatenar
print("a decimal:", float("2.5") + 1)         # 3.5

como texto: 1500 pesos

Por qué "3" + "3" no es 6

Si sumás dos textos, Python los pega: "3" + "3" da "33", no 6. Y "3" * 2 da "33" (repite el texto). Por eso, cuando un número te llega como texto, tenés que convertirlo con int() antes de operar. Es una fuente clásica de bugs: revisá los tipos con type() si un cálculo da cualquier cosa.

input: pedirle datos al usuario

La función input() muestra un mensaje y espera a que el usuario escriba algo y apriete Enter. Devuelve siempre texto, así que casi siempre lo convertís.

Fijate el int(input(...)): primero input trae el texto, después int lo convierte a número para poder multiplicar. Sin esa conversión, cantidad sería texto y el cálculo fallaría.

Ojo: el usuario escribe cualquier cosa

¿Qué pasa si a "¿cuántas pizzas?" el usuario escribe "dos" en vez de "2"? El int() falla con un error. Los programas robustos anticipan esto y lo manejan con try/except (Parte 7). Por ahora, tené en cuenta que todo dato que viene de afuera puede venir "mal": validarlo es parte del oficio.

Capítulo 10

Condicionales: if / elif / else

Hasta ahora los programas iban en línea recta: instrucción tras instrucción. Los condicionales le dan al programa la capacidad de decidir: hacer una cosa u otra según la situación. "Si hay stock, vendé; si no, avisá." Es el primer gran salto en poder.

El if básico

01_fundamentos.py
stock = 5
pedido = 8
if pedido <= stock:
    print("hay stock")
elif pedido - stock <= 3:
    print("falta poco, reponer")
else:
    print("sin stock suficiente")
salida real✓ salida real
falta poco, reponer

Cómo se lee, línea por línea

Python evalúa de arriba a abajo. Primero: ¿el pedido (8) es menor o igual al stock (5)? No, es falso, así que salta ese bloque. Después el elif ("si no, y si..."): ¿la diferencia (8-5=3) es menor o igual a 3? Sí → ejecuta ese bloque y muestra "falta poco". El else ("si no, entonces") es lo que pasa cuando ninguna condición anterior se cumplió; acá no llegó porque el elif ya dio verdadero. En cuanto una condición se cumple, ejecuta su bloque y se saltea el resto.

Las tres piezas

  • if (si): la primera condición. Es obligatoria.
  • elif (contracción de "else if"): condiciones adicionales, tantas como quieras. Es opcional.
  • else (si no): el caso "para todo lo demás". Opcional, y no lleva condición.

La sangría no es decoración

Fijate que las líneas dentro de cada if están corridas hacia la derecha (4 espacios). En Python, esa sangría (indentación) es cómo el lenguaje sabe qué código pertenece a qué bloque. Todo lo que esté sangrado debajo del if: se ejecuta si la condición se cumple. Y ojo con los dos puntos : al final de la línea del if: son obligatorios.

un if simple, sin elif ni else
edad = 20
if edad >= 18:
    print("es mayor de edad")
    print("puede entrar")     # este también está dentro del if
print("esta línea siempre se ejecuta")  # esta NO está sangrada: siempre corre
El error de sangría

Es el error número uno al empezar con Python. Mezclar espacios y tabulaciones, o poner distinta cantidad de espacios, hace que Python se queje con un IndentationError. La regla salvadora: usá siempre 4 espacios, nunca mezcles con tabs, y sé consistente. Los buenos editores lo hacen por vos.

Condiciones compuestas y anidadas

Las decisiones reales suelen combinar varias condiciones. "Si hay stock Y está pago, preparar el pedido." Para eso usamos los and, or y not del capítulo de booleanos, ahora dentro de los if.

Condiciones anidadas

A veces una decisión depende de otra. Podés poner un if dentro de otro: eso es "anidar".

anidado
if pedido <= stock:
    if pagado:
        print("preparar")
    else:
        print("hay stock, falta el pago")

    print("sin stock")
Anidar poco, combinar mejor

Anidar muchos if dentro de otros vuelve el código difícil de seguir (la "escalera al infierno"). Muchas veces se puede aplanar combinando condiciones con and, o resolviendo primero los casos que cortan (ver abajo). Si te encontrás con tres o cuatro niveles de sangría, pará y buscá simplificar.

El patrón de "salida temprana"

Un truco de código limpio: en vez de anidar, resolvé primero lo que descarta, y seguí. Compará con el anidado de arriba:

salida temprana (dentro de una función)
def preparar(pedido, stock, pagado):
    if pedido > stock:
        return "sin stock"        # corta acá si no hay stock
    if not pagado:
        return "falta el pago"    # corta acá si no está pago
    return "preparar"             # si llegó hasta acá, todo bien

Cada return corta la función. Así vas descartando casos malos al principio, y al final queda el caso bueno, sin anidar. Es un patrón que vas a ver mucho, y que hace el código mucho más legible.

El bucle for: repetir para cada cosa

La computadora brilla repitiendo. El bucle for recorre una colección (una lista, un rango de números, un texto) y ejecuta el mismo bloque para cada elemento. Es el bucle que más vas a usar.

for con range

Capítulo 13

El bucle while: repetir mientras...

El for repite un número conocido de veces (por cada elemento). El while repite mientras se cumpla una condición, sin saber de antemano cuántas veces. "Mientras el usuario no elija salir", "mientras quede stock".

Cómo funciona

cuenta regresiva
n = 3
while n > 0:
    print(n)
    n = n - 1     # ¡clave! achicamos n para que el bucle termine
salida real✓ salida real
3
2
1

Se lee: "mientras n sea mayor que 0, mostrá n y restale 1". Python evalúa la condición antes de cada vuelta. Cuando n llega a 0, la condición n > 0 es falsa y el bucle termina.

El temido bucle infinito

MAL: esto no termina nunca
n = 3
while n > 0:
    print(n)
    # nos olvidamos de restar: n siempre vale 3, la condición siempre es True
Todo while necesita una salida

Si dentro del while nada cambia lo que evalúa la condición, se repite para siempre y el programa se cuelga. Cada while necesita que algo adentro, tarde o temprano, haga que la condición sea falsa (un contador que baja, una variable que cambia, un break). Si tu programa "se queda pensando" sin terminar, sospechá de esto. Para cortarlo a mano: Ctrl+C en la consola.

El patrón de menú (while + input)

Un uso clásico del while: repetir hasta que el usuario elija salir.

menú interactivo
opcion = ""
while opcion != "salir":
    opcion = input("Escribí una opción (o 'salir'): ")
    if opcion != "salir":
        print("elegiste:", opcion)
print("¡Chau!")

El bucle sigue mientras la opción no sea "salir". Cuando el usuario escribe "salir", la condición se vuelve falsa y el programa termina. Este patrón es la base de cualquier programa interactivo de consola.

for o while: cuál elegir

Regla práctica: si sabés sobre qué repetir (una lista, un rango), usá for. Si repetís hasta que pase algo (el usuario sale, se acaba el stock, se cumple una condición), usá while. El for es más común y más seguro (no se cuelga); el while es para cuando no sabés cuántas vueltas van a ser.

break y continue

Capítulo 15

Listas: muchos valores en orden

Una variable guarda un valor. Una lista guarda muchos, en orden, bajo un solo nombre. "Los productos del menú", "los precios de hoy", "los pedidos pendientes": todo eso son listas. Es la estructura de datos que más vas a usar.

Crear y acceder

01_fundamentos.py
productos = ["empanada", "pizza", "flan"]
print("primero:", productos[0])       # empanada (se cuenta desde 0)
print("último:", productos[-1])        # flan (negativo desde el final)
print("cuántos:", len(productos))      # 3

Se crean entre corchetes, con los elementos separados por comas. Se accede por posición, empezando en 0: el primero es [0], el segundo [1]. Los negativos cuentan desde atrás: [-1] es el último. len() te dice cuántos hay.

Modificar una lista

agregar, sacar, cambiar
productos = ["empanada", "pizza", "flan"]

productos.insert(0, "agua")        # agregar en una posición
productos.remove("pizza")          # sacar por valor
ultimo = productos.pop()           # sacar el último y devolverlo

print(productos)
MétodoQué hace

.insert(i, x)inserta x en la posición i
.remove(x)saca la primera aparición de x
.pop()saca y devuelve el último (o el de una posición)
.sort()ordena la lista

Recorrer y preguntar

01_fundamentos.py
productos = ["empanada", "pizza", "flan", "gaseosa"]
for p in productos:
    print("  -", p)

  - pizza
  - flan
  - gaseosa

El for recorre la lista elemento por elemento (lo viste en la Parte 3). El operador in pregunta si algo está en la lista, y da un booleano. Con len, sum, max, min sacás cuenta rápida de una lista de números.

Se cuenta desde CERO

Insisto porque es la trampa clásica: la primera posición es 0, no 1. En una lista de 4 elementos, las posiciones válidas van de 0 a 3. Pedir productos[4] en esa lista da un error IndexError ("index out of range"). Cuando lo veas, casi siempre es esto: te pasaste por uno.

Una tupla es como una lista, pero con una diferencia clave: una vez creada, no se puede modificar. Se usa para datos que van juntos y no deberían cambiar: unas coordenadas, un par (nombre, precio), un registro fijo.

Desempaquetar tuplas

Un truco muy usado: asignar los valores de una tupla a varias variables de una vez.

desempaquetar

Usá una lista cuando la colección va a cambiar (agregar/sacar productos). Usá una tupla cuando son datos fijos que van juntos y no deben cambiar (un par nombre-precio, una coordenada). Capítulo 17

Diccionarios: datos con etiqueta

Una lista guarda cosas en orden, numeradas. Un diccionario las guarda con nombre: pares de "clave: valor". Es perfecto para los datos de una cosa: un pedido tiene un producto, una cantidad, un precio. En vez de recordar "la posición 2 es el precio", accedés por el nombre.

Crear y acceder

01_fundamentos.py
pedido = {"producto": "pizza", "cantidad": 2, "precio": 8500}
print("cantidad:", pedido["cantidad"])   # 2 (accedo por la clave)
pedido["pagado"] = True                    # agregar un dato nuevo
print(pedido)
salida real✓ salida real
el pedido es de 2 pizza
{'producto': 'pizza', 'cantidad': 2, 'precio': 8500, 'pagado': True}

Se crean con llaves {}, con clave: valor separados por comas. Accedés a un valor por su clave entre corchetes: pedido["precio"]. Agregás o cambiás datos asignando a una clave.

Acceso seguro con get

get: sin romper si no existe
pedido = {"producto": "pizza", "cantidad": 2}
print(pedido.get("precio"))            # None (no existe, pero no rompe)
print(pedido.get("precio", 0))          # 0 (valor por defecto si no está)
# pedido["precio"]  # ESTO daría error KeyError porque la clave no existe

Acceder con corchetes a una clave que no existe da error. Con .get(), si no existe devuelve None (o el valor por defecto que le pases). Útil cuando no estás seguro de que la clave esté.

Recorrer un diccionario

recorrer claves y valores
pedido = {"producto": "pizza", "cantidad": 2, "precio": 8500}
for clave, valor in pedido.items():
    print(f"  {clave}: {valor}")
print("claves:", list(pedido.keys()))
print("valores:", list(pedido.values()))

.items() te da pares (clave, valor) para recorrer con for. .keys() da las claves y .values() los valores. Es lo que usás para procesar todos los datos de un registro.

Lista o diccionario

La regla de oro: lista para muchas cosas del mismo tipo (muchos productos); diccionario para varios datos de una misma cosa (los datos de un pedido). Y se combinan: una lista de diccionarios es "muchos pedidos, cada uno con sus datos". Esa combinación es cómo se representan los datos en prácticamente toda aplicación, y es el próximo tema.

Capítulo 18

Conjuntos (sets): sin duplicados

Un set es una colección sin orden y sin elementos repetidos. Su superpoder es justamente ese: eliminar duplicados y responder rapidísimo "¿está esto acá?". Se usa menos que listas y diccionarios, pero para lo suyo es imbatible.

c16_estructuras.py
tags = {"oferta", "nuevo", "oferta"}   # el "oferta" repetido se ignora
print("set sin duplicados:", tags)
print("está 'nuevo'?:", "nuevo" in tags)
salida real✓ salida real
set sin duplicados: {'oferta', 'nuevo'}
esta 'nuevo'?: True

El uso más común: sacar duplicados de una lista

quitar repetidos
clientes = ["Ana", "Luis", "Ana", "Marta", "Luis"]
unicos = list(set(clientes))       # convertir a set saca duplicados
print("clientes únicos:", unicos)
print("cuántos distintos:", len(set(clientes)))   # 3

Convertir una lista a set y de vuelta a lista es la forma rápida de eliminar repetidos. Y como el set no permite duplicados, len(set(...)) te dice cuántos valores distintos hay.

Cuándo un set

Usá un set cuando el orden no importa y no querés duplicados: etiquetas, valores únicos, "¿ya vi este?". Preguntar x in mi_set es muchísimo más rápido que en una lista grande, así que si vas a chequear pertenencia muchas veces sobre muchos datos, un set es la herramienta. Capítulo 19

Estructuras anidadas: la lista de diccionarios

Acá se junta todo. Los datos reales no son valores sueltos: son colecciones de registros. Un menú es una lista de productos, y cada producto es un diccionario con sus datos. Esta combinación (lista de diccionarios) es LA forma de representar datos en casi toda aplicación. Dominarla es clave.

Un menú de verdad

c16_estructuras.py
menu = [
    {"nombre": "Pizza", "precio": 8500},
    {"nombre": "Flan", "precio": 3500},
    {"nombre": "Gaseosa", "precio": 1800},
]
for item in menu:
    print(f"  {item['nombre']}: ${item['precio']}")
salida real✓ salida real
  Pizza: $8500
  Flan: $3500
  Gaseosa: $1800

La lista tiene tres elementos, y cada uno es un diccionario. El for recorre la lista; adentro, item es un diccionario, así que accedés a sus datos con item["nombre"]. Leelo despacio: lista por fuera, diccionario por dentro.

Operar sobre la colección

c16_estructuras.py
total = sum(item["precio"] for item in menu)   # sumar todos los precios

mas_caro = max(menu, key=lambda x: x["precio"])  # el de mayor precio

total del menu: 13800
mas caro: Pizza

El sum(item["precio"] for item in menu) suma el precio de cada item (es un acumulador, compacto). No te preocupes por el lambda ahora (es una función corta sin nombre); lo importante es el patrón.

Esto es cómo llegan los datos de verdad

Cuando pidas datos a una API (librito 01) o a una base (librito 10), casi siempre llegan como una lista de diccionarios: una lista de productos, de usuarios, de pedidos, cada uno un diccionario con sus campos. Capítulo 20

Funciones: empaquetar y reutilizar

Una función es un bloque de código con nombre, que hace una tarea y podés usar cuantas veces quieras. Son la herramienta más importante para organizar un programa: en vez de repetir el mismo cálculo en diez lugares, lo escribís una vez y lo llamás por su nombre.

Definir y llamar

02_funciones_poo.py
def con_descuento(precio, porcentaje):
    return precio - (precio * porcentaje / 100)

print("1000 con 25% off:", con_descuento(1000, 25))
print("8500 con 10% off:", con_descuento(8500, 10))
salida real✓ salida real
1000 con 25% off: 750.0
8500 con 10% off: 7650.0

Las partes de una función

  • def arranca la definición, seguido del nombre y paréntesis.
  • Entre paréntesis van los parámetros: los datos que la función recibe (precio, porcentaje).
  • El cuerpo va sangrado (como en el if).
  • return es el resultado que la función entrega. Cuando Python llega al return, la función termina y devuelve ese valor.
  • Para usarla, la llamás con valores concretos: con_descuento(1000, 25).

Definir no es ejecutar

Un detalle importante: cuando escribís def, la función queda definida pero no corre. Recién se ejecuta cuando la llamás. Es como una receta escrita: existe, pero no cocina nada hasta que alguien la sigue. Podés definir una función arriba y llamarla muchas veces abajo.

return vs print

la diferencia clave
def suma_print(a, b):
    print(a + b)        # muestra, pero no devuelve nada usable

def suma_return(a, b):
    return a + b        # devuelve el valor, que podés seguir usando

x = suma_return(2, 3)   # x vale 5, puedo usarlo
total = x * 10          # 50
# y = suma_print(2, 3)  # muestra 5, pero y queda en None (no sirve para calcular)
return y print no son lo mismo

Confusión clásica del principio. print muestra algo en pantalla y ya. return entrega un valor que el resto del programa puede usar (guardar, sumar, pasar a otra función). Una función que calcula debe returnar su resultado; si solo hace print, el valor se "pierde" apenas se muestra. Regla: si vas a usar el resultado, return.

Capítulo 22

Ámbito (scope) y buenas prácticas

Un tema que confunde y conviene entender temprano: dónde "viven" las variables. Una variable creada dentro de una función existe solo ahí adentro. Eso se llama ámbito (scope), y es una buena cosa: mantiene las funciones independientes.

Las variables locales no salen de la función

c21_funciones.py
def f():
    x = 10          # x vive solo dentro de f
    return x

print("retorno:", f())   # 10
# print(x)   # ESTO daría error: x no existe acá afuera
salida real✓ salida real
retorno: 10

La variable x nace y muere dentro de f. Afuera no existe. Por eso, para "sacar" un valor de una función, se usa return. Esto es bueno: cada función es una cajita cerrada, y no se pisan variables entre funciones sin querer.

Docstrings: documentar una función

una función bien documentada
def total_pedido(precio, cantidad, descuento=0):
    """Calcula el total de un pedido con un descuento opcional (0 a 1)."""
    subtotal = precio * cantidad
    return subtotal * (1 - descuento)

El texto entre triples comillas justo debajo del def es un "docstring": describe qué hace la función. No es obligatorio, pero es una gran costumbre: quien use la función (o vos en un mes) entiende qué hace sin leer el código.

Buenas prácticas de funciones

  • Una función, una tarea. Si hace muchas cosas, partila en varias.
  • Nombre que diga qué hace: calcular_total, no hacer_cosa.
  • Cortita. Si no entra en una pantalla, probablemente convenga dividirla.
  • Que reciba lo que necesita por parámetros y devuelva su resultado con return, en vez de depender de variables de afuera.
Por qué funciones, en una frase

Las funciones te dan tres cosas: no repetís código, le ponés nombre a las ideas (el programa se lee mejor), y si hay que corregir algo, lo cambiás en un solo lugar. Son el primer paso hacia programas grandes que no se vuelven un caos. La programación orientada a objetos, que viene ahora, lleva esta idea un paso más allá.

Capítulo 23

Programación orientada a objetos

La POO es una forma de organizar el código que agrupa los datos de una cosa junto con las acciones que operan sobre esos datos. Suena abstracto; con el ejemplo del producto se vuelve concreto. Un producto tiene datos (nombre, precio, stock) y cosas que puede hacer (venderse, revisar su stock). Una clase junta las dos cosas en un solo lugar.

Clase = molde, objeto = cosa concreta

Una clase es el molde que describe cómo es algo. Un objeto es cada cosa concreta hecha con ese molde. La clase Producto describe qué tiene y qué hace cualquier producto; pizza y gaseosa son dos objetos hechos con ese molde, cada uno con sus propios datos.

02_funciones_poo.py
class Producto:
    def __init__(self, nombre, precio, stock):
        self.nombre = nombre        # atributos: los datos del objeto
        self.precio = precio
        self.stock = stock

    def hay_stock(self, cantidad):  # métodos: lo que el objeto puede hacer
        return self.stock >= cantidad

Crear objetos a partir de la clase

crear y usar
pizza = Producto("Pizza muzza", 8500, 5)   # crear un objeto
gaseosa = Producto("Gaseosa", 1800, 20)     # otro, independiente
print(pizza.nombre, "cuesta", pizza.precio, "y hay", pizza.stock)
print("¿alcanza para 3 pizzas?:", pizza.hay_stock(3))

Pizza muzza cuesta 8500 y hay 5

Creás un objeto llamando a la clase como si fuera una función: Producto("Pizza muzza", 8500, 5). Eso ejecuta el __init__ y guarda los datos. Después accedés a sus atributos con punto (pizza.nombre) y llamás sus métodos igual (pizza.hay_stock(3)). Cada objeto tiene sus propios datos: la pizza y la gaseosa no se pisan.

Las dos palabras raras

__init__ es el "constructor": se ejecuta automáticamente al crear el objeto, y ahí se guardan los datos iniciales. self significa "este objeto en particular": self.stock es el stock de esta pizza puntual, distinto del de la gaseosa. Las dos suenan raras las primeras veces; después se vuelven automáticas. Todos los métodos reciben self como primer parámetro.

Capítulo 24

Métodos que cambian el estado del objeto

Lo interesante de un objeto es que recuerda su estado y lo cambia. Un producto que se vende tiene menos stock después. El método vender modifica el self.stock del objeto, y ese cambio persiste.

02_funciones_poo.py
class Producto:
    def __init__(self, nombre, precio, stock):
        self.nombre = nombre
        self.precio = precio
        self.stock = stock

    def hay_stock(self, cantidad):
        return self.stock >= cantidad

    def vender(self, cantidad):
        if not self.hay_stock(cantidad):
            return f"sin stock de {self.nombre} (quedan {self.stock})"
        self.stock -= cantidad            # cambia el estado del objeto
        return f"vendidas {cantidad} de {self.nombre}, quedan {self.stock}"
el objeto recuerda entre llamadas
pizza = Producto("Pizza muzza", 8500, 5)
print(pizza.vender(2))
print(pizza.vender(2))
print(pizza.vender(2))   # este se pasa: solo queda 1
salida real✓ salida real
Pizza muzza cuesta 8500 y hay 5
vendidas 2 de Pizza muzza, quedan 3
vendidas 2 de Pizza muzza, quedan 1
sin stock de Pizza muzza (quedan 1)

Qué pasó, paso a paso

La pizza empieza con stock 5. La primera venta de 2 lo baja a 3. La segunda, a 1. La tercera pide 2, pero hay_stock(2) es falso (solo queda 1), así que vender devuelve el mensaje de "sin stock" sin tocar nada. El objeto recordó su stock entre una llamada y otra: eso es el estado. Un método (vender) usa a otro (hay_stock) del mismo objeto, con self..

Datos y lógica, juntos

Fijate lo prolijo: el producto sabe cuánto stock tiene Y sabe controlarlo al vender. Los datos y la lógica que los cuida viven en el mismo lugar. Nadie puede vender más de lo que hay sin pasar por vender, que lo controla. Esa es la gran ventaja de la POO: el objeto protege sus propios datos y garantiza que se usen bien.

Capítulo 25

Varios objetos que trabajan juntos

Los programas reales tienen muchos objetos de distintas clases que colaboran. Un carrito contiene productos y les pide que se vendan. Ver cómo un objeto usa a otro es entender de qué está hecho el software.

c26_poo.py
class Carrito:
    def __init__(self):
        self.items = []       # lista de lo agregado
        self.total = 0

    def agregar(self, producto, cantidad):
        importe = producto.vender(cantidad)   # el carrito le pide al producto que se venda
        self.items.append((producto.nombre, cantidad, importe))
        self.total += importe

    def resumen(self):
        for nombre, cant, imp in self.items:
            print(f"  {cant}x {nombre} = ${imp}")
        print(f"  TOTAL: ${self.total}")

El Carrito no sabe cómo un producto controla su stock: solo le pide producto.vender(cantidad) y confía en que el producto sabe hacerlo. Así se construye el software

Este reparto (cada objeto hace su parte, y colaboran) es la esencia del diseño de software. Un sistema grande es muchos objetos de muchas clases pasándose mensajes. La tienda del librito 13 es exactamente esto en grande: productos, pedidos, pagos, cada uno una clase que hace lo suyo. Lo que acabás de ver es el modelo mental de todo eso.

Capítulo 26

Herencia: reutilizar y especializar

A veces una clase es una versión especial de otra. Un producto con descuento ES un producto, con algo extra. La herencia te deja crear una clase basada en otra, heredando todo lo que ya tiene y agregando o cambiando lo que necesites, sin repetir código.

c26_poo.py
class ProductoConDescuento(Producto):     # hereda de Producto
    def __init__(self, nombre, precio, stock, descuento):
        super().__init__(nombre, precio, stock)   # reusa el init del padre
        self.descuento = descuento                 # y agrega lo suyo

    def vender(self, cantidad):                     # cambia el comportamiento
        base = super().vender(cantidad)             # usa el vender del padre
        return base * (1 - self.descuento)          # y le aplica el descuento
usarla
flan = ProductoConDescuento("Flan", 3500, 8, 0.20)
print("flan con 20% off, 2 unidades:", flan.vender(2))
salida real✓ salida real
flan con 20% off, 2 unidades: 5600.0

Qué pasó

ProductoConDescuento(Producto) significa "esta clase hereda de Producto": arranca con todo lo que Producto tiene (nombre, precio, stock, hay_stock). super() se refiere a la clase padre: super().__init__(...) reusa su constructor, y super().vender(...) reusa su venta, a la que después le aplica el descuento. El flan de 3500 × 2 = 7000, con 20% off = 5600. No reescribimos nada de Producto: lo aprovechamos.

Herencia: usar con criterio

La herencia es potente pero se abusa. La regla sana: usala cuando de verdad hay una relación "es un/una" (un ProductoConDescuento es un Producto). Si solo querés reusar código sin esa relación, muchas veces es mejor que un objeto tenga a otro (como el carrito tiene productos, capítulo 25). Por ahora, alcanza con entender la idea: heredar lo que ya existe y especializarlo.

Los errores son parte de programar, no un fracaso. Cómo se piensa un problema

Ya tenés todas las herramientas de Python. Ahora lo más importante y lo que menos se enseña: cómo pasar de "quiero que haga X" a código. El secreto no es saber más Python, es pensar el problema en pasos chiquitos antes de escribir una sola línea.

Capítulo 33 · Ejercicio

Descuentos por cantidad (escalonados)

Subimos un escalón. Ahora el descuento depende de cuánto se compra: 0% hasta 2 unidades, 10% de 3 a 5, y 20% de 6 en adelante. Esto necesita decidir el descuento según la cantidad, con un if/elif/else, y después aplicarlo.

La receta

cómo lo pensás
1. Según la cantidad, elegir el porcentaje de descuento (un if escalonado)
2. Calcular el subtotal (precio x cantidad)
3. Aplicar el descuento elegido

El truco del if escalonado: chequear de mayor a menor. Si preguntás primero por 6+, después por 3+, el que llega a 4 falla el primero y entra en el segundo, correcto. Si lo hicieras al revés, un pedido de 8 entraría en "3 o más" y nunca llegaría al 20%.

El código

e_escalonado.py
def descuento_por_cantidad(cantidad):
    if cantidad >= 6: return 0.20
    if cantidad >= 3: return 0.10
    return 0.0

def total(precio, cantidad):
    subtotal = precio * cantidad
    desc = descuento_por_cantidad(cantidad)
    return subtotal * (1 - desc), desc     # devuelve total y descuento

for c in [1, 4, 8]:
    t, d = total(1200, c)
    print(f"{c} empanadas: ${t:.0f}  (descuento {int(d*100)}%)")
salida real✓ salida real
1 empanadas: $1200  (descuento 0%)
4 empanadas: $4320  (descuento 10%)
8 empanadas: $7680  (descuento 20%)

Separamos la decisión (descuento_por_cantidad) del cálculo (total): cada función hace una cosa. El for prueba con 1, 4 y 8 unidades, y cada una cae en su escalón. 1 empanada sin descuento, 4 con 10%, 8 con 20%. Fijate que total devuelve dos valores (el total y el descuento), que recibimos con t, d = (cap. 21).

El orden de los if importa

En un if/elif escalonado, el orden de las condiciones es todo. Chequeá siempre del caso más restrictivo al menos (de 6+ hacia 3+ hacia el resto). Es un error clásico ponerlos al revés y que un caso "se coma" a otro. Cuando algo cae en el escalón equivocado, revisá el orden.

Capítulo 34 · Ejercicio

Dos pedidos, y el segundo se queda sin stock

Un ejercicio que junta casi todo. Entran dos pedidos, solo quedan 3 unidades, y cada uno pide 2. El primero entra bien; el segundo no tiene stock suficiente. El programa tiene que darse cuenta y rechazarlo. Usamos variables, un bucle, un if, y el descuento del ejercicio 32.

La clave del problema

Lo importante: el stock cambia entre un pedido y el otro. Después del primero quedan menos unidades, y con eso se evalúa el segundo. Por eso el stock es una variable que actualizamos dentro del bucle, no un valor fijo.

La receta en palabras

cómo lo pensás

      NO  -> lo rechazo y aviso cuántos faltan

precio_unitario = 8500

        total = subtotal - subtotal * 25 / 100  # con 25% off
        stock = stock - cantidad                # descontamos del stock
        print(f"  OK. Total con 25% off: ${total:.0f}")
        print(f"  stock restante: {stock}")
    else:
        faltan = cantidad - stock

Qué pasó, paso a paso

El primer pedido pide 2 y hay 3: entra. Se cobra con descuento ($12750, el mismo cálculo del ejercicio 32) y el stock baja a 1. El segundo pide 2, pero ahora solo queda 1: la condición cantidad <= stock es falsa, entra al else y lo rechaza, avisando que falta 1. Ese "el stock cambió entre un pedido y otro" es exactamente lo que hace un sistema real.

Capítulo 35 · Ejercicio

Un carrito completo con objetos

El mismo problema del stock, ahora resuelto con objetos (Parte 6). Un Producto que controla su stock, y un Carrito que junta productos y suma. Compará con el ejercicio anterior: la lógica es la misma, pero organizada en clases, más parecida a un sistema real.

c26_poo.py
class Producto:
    def __init__(self, nombre, precio, stock):
        self.nombre, self.precio, self.stock = nombre, precio, stock
    def vender(self, cantidad):
        if cantidad > self.stock:
            raise ValueError(f"sin stock de {self.nombre} (quedan {self.stock})")
        self.stock -= cantidad
        return self.precio * cantidad

class Carrito:
    def __init__(self):
        self.items = []
        self.total = 0
    def agregar(self, producto, cantidad):
        importe = producto.vender(cantidad)   # le pide al producto que se venda
        self.items.append((producto.nombre, cantidad, importe))
        self.total += importe
    def resumen(self):
        for nombre, cant, imp in self.items:
            print(f"  {cant}x {nombre} = ${imp}")
        print(f"  TOTAL: ${self.total}")

Fijate la diferencia con el ejercicio 34

Antes, el stock era una variable suelta y la lógica estaba toda junta en el bucle. Ahora cada producto cuida su propio stock (en vender), y el carrito solo coordina. Es más código, pero más ordenado y más fácil de crecer: agregar un producto nuevo, o un descuento (con herencia, cap. 26), no toca el carrito. Así se organizan los sistemas de verdad.

Cuándo POO y cuándo no

Para un cálculo puntual (el ejercicio 34), variables y funciones alcanzan y sobran. Para un sistema con muchas entidades que interactúan y crecen (productos, pedidos, usuarios), la POO paga: mantiene todo ordenado. No uses objetos porque sí; usalos cuando el problema tiene "cosas" con datos y comportamiento. Con la práctica, la intuición llega sola.

Qué es un div y una lista, en el fondo

El HTML es texto con "etiquetas" que envuelven contenido. Un <div> es una caja que agrupa cosas. Una lista es un <ul> (la lista) con varios <li> adentro (cada ítem). Las etiquetas se abren con <etiqueta> y se cierran con </etiqueta>.

La forma de una petición

    fila = con.execute("SELECT precio, stock FROM productos WHERE nombre=?",
                       (nombre,)).fetchone()
    if fila is None:
        return f"no existe {nombre}"

               (cantidad, nombre))
    con.commit()

List comprehensions: transformar colecciones

Un patrón que aparece constantemente: tomar una lista y producir otra (transformando o filtrando). Ya lo hiciste con bucles. Python tiene una forma compacta y elegante de hacerlo en una línea: las "list comprehensions". Una vez que las agarrás, no querés volver atrás.

Del bucle a la comprehension

Compará las dos formas de aplicarle IVA a una lista de precios:

el bucle de siempre
con_iva = []
for p in precios:
    con_iva.append(p * 1.21)
la misma idea, en una línea
con_iva = [p * 1.21 for p in precios]

Se lee: "para cada p en precios, poné p * 1.21". El resultado es una lista nueva. Es exactamente lo mismo que el bucle, más corto y más claro una vez acostumbrado.

Transformar, filtrar, y las dos cosas

c_comprehensions.py
precios = [1200, 8500, 3500, 9800, 1800]
con_iva = [p * 1.21 for p in precios]              # transformar
caros = [p for p in precios if p > 5000]           # filtrar (con if al final)
nombres = ["pizza", "flan", "gaseosa"]
largos = [n.upper() for n in nombres if len(n) > 4] # transformar + filtrar
salida real✓ salida real
con IVA: [1452, 10285, 4235, 11858, 2178]
caros: [8500, 9800]
largos en mayus: ['PIZZA', 'GASEOSA']

El if al final filtra: solo entran los que cumplen. Así, en una línea, transformás y seleccionás. Es el patrón "filtrar" del capítulo 14, comprimido.

zip junta dos (o más) listas elemento a elemento, para recorrerlas en paralelo. Y las comprehensions también sirven para diccionarios (con {clave: valor for ...}). Son herramientas de todos los días en Python.

No abuses: legibilidad primero

Las comprehensions son geniales para transformaciones simples. Pero si le metés dos for y tres if, se vuelven ilegibles: ahí es mejor un bucle normal. La regla: si no la entendés de un vistazo, usá el bucle. La compacidad no vale si nadie entiende el código (capítulo 42).

strftime ("string from time") le da formato a una fecha: %d día, %m mes, %Y año, %H hora, %M minutos. timedelta representa una duración: sumarla o restarla a una fecha te da otra fecha, resolviendo bien fines de mes y años bisiestos.

Restar fechas y trabajar con hora

Restar dos fechas da un timedelta, y su .days te dice cuántos días hay entre ellas. datetime (con hora) es como date pero incluye hora y minutos, útil para marcar cuándo pasó algo (como el creado_en de un pedido). Para la fecha de hoy de verdad: date.today().

Nunca calcules fechas a mano

"Sumar 30 días" no es "cambiar el mes": los meses tienen 28, 30 o 31 días, y hay años bisiestos. timedelta maneja todo eso por vos. Y para guardar fechas (en un archivo, una base), el formato estándar es "aaaa-mm-dd" (el que muestra Python por defecto): ordena bien y no se confunde con el día/mes. Es el que usa todo el track de Datos.

Capítulo 46

JSON: guardar y compartir datos

JSON es el formato en que viajan los datos por internet y el más común para guardarlos en archivos. La buena noticia: es prácticamente igual a los diccionarios y listas de Python que ya conocés. Aprenderlo es media hora bien invertida, porque está en todos lados.

Qué es JSON

JSON (JavaScript Object Notation) es texto con una estructura: objetos entre {} (como los diccionarios) y listas entre [] (como las listas). Cuando una API te manda datos (librito 01), casi siempre es JSON. Cuando guardás datos estructurados en un archivo, JSON es una gran opción.

De Python a JSON y de vuelta

print(texto)

recuperado = json.loads(texto)                    # texto JSON -> objeto Python
print("cliente:", recuperado["cliente"])
print("primer item:", recuperado["items"][0]["producto"])

Capítulo 47

Anotaciones de tipo (type hints)

Python te deja (opcionalmente) escribir de qué tipo es cada cosa: que un parámetro es un número, que una función devuelve texto. No cambia cómo corre el programa, pero documenta, previene errores, y hace que tu editor te ayude muchísimo más. En proyectos serios se usan siempre.

Tipar funciones y variables

c_typehints.py
def total_pedido(precio: float, cantidad: int, descuento: float = 0.0) -> float:
    subtotal = precio * cantidad
    return subtotal * (1 - descuento)

nombre: str = "Pizza"
precios: list[int] = [1200, 8500]
menu: dict[str, int] = {"pizza": 8500}
salida real✓ salida real
12750.0
las anotaciones no cambian el resultado, guían y documentan

Después de cada parámetro, : tipo dice qué se espera. La flecha -> float al final dice qué devuelve la función. En variables, nombre: str. Los tipos de colecciones se escriben list[int] (lista de enteros), dict[str, int] (diccionario de texto a entero).

Por qué molestarse

  • Documentación que no miente: quien usa total_pedido sabe que recibe números y devuelve un número, sin leer el código.
  • Tu editor te ayuda: autocompleta mejor y te avisa si pasás el tipo equivocado.
  • Herramientas que revisan: programas como mypy chequean los tipos antes de correr y atrapan bugs.
Puente al librito de TypeScript

Esto es exactamente la idea de TypeScript (librito 14) pero en Python: agregar tipos para atrapar errores antes y documentar. En Python son opcionales (el programa corre igual sin ellos); en TypeScript son el centro del lenguaje. Si entendiste esto, ya entendés de qué se trata TypeScript. Empezá a usar type hints en tus funciones importantes: es un hábito que paga.

Capítulo 48

Depurar: encontrar y arreglar errores

Vas a pasar más tiempo arreglando código que escribiéndolo, y eso es normal, incluso para los expertos. Depurar (encontrar y corregir errores) es una habilidad en sí misma, y la buena noticia es que se aprende. Acá van las técnicas que de verdad se usan.

1. Leer el error (bien)

Cuando Python falla, te da un "traceback". No lo ignores: leelo de abajo hacia arriba. La última línea dice qué pasó y las de arriba, dónde. La mayoría de los errores se resuelven solo leyendo esto con atención.

un traceback, traducido
Traceback (most recent call last):
  File "tienda.py", line 12, in <module>
    total = precio * cantidad
TypeError: can't multiply sequence by non-int of type 'str'
   ^-- QUÉ pasó: intentaste multiplicar algo con un texto
       DÓNDE: línea 12, en total = precio * cantidad
       CAUSA probable: precio o cantidad es texto, no número (¿faltó int()?)

2. print para espiar

La técnica más usada del mundo, sin exagerar. Cuando algo da un valor raro, poné print antes para ver qué hay en cada variable:

print-debugging
def total(precio, cantidad):
    print("DEBUG precio:", precio, type(precio))     # espiamos
    print("DEBUG cantidad:", cantidad, type(cantidad))
    return precio * cantidad

Ver el valor y el tipo (con type()) resuelve la mayoría de los misterios: casi siempre una variable no tiene lo que creías (un número que era texto, una lista vacía, un None). Después borrás los prints.

3. El método: dividir y achicar

  • Reproducí el error: encontrá los pasos exactos que lo disparan.
  • Achicá: comentá partes del código hasta aislar la línea culpable.
  • Una hipótesis por vez: "creo que es esto" → probalo → confirmá o descartá. No cambies cinco cosas a la vez.
  • El patito de goma: explicá el problema en voz alta, línea por línea. Muchas veces, explicándolo, encontrás el error solo. En serio.
Los errores no son fracasos

Cambiá el chip: un error no es que "sos malo programando", es información. El programa te está diciendo exactamente qué no le cierra. Los programadores con años no cometen menos errores; los encuentran y arreglan más rápido, porque practicaron esto. Cada bug que resolvés te hace mejor. Frustrarse es parte del proceso; rendirse en el primer error rojo, no.

Capítulo 49

De un script a un programa organizado

Al principio, todo va en un archivo, de arriba a abajo. Funciona para lo chico. Cuando el programa crece, conviene organizarlo: separar en funciones, repartir en archivos, y saber instalar librerías. Un vistazo a cómo se estructura un proyecto de verdad.

Primero, funciones; después, archivos

El primer paso de orden es agrupar el código en funciones (Parte 5), cada una con su tarea. El segundo, cuando hay muchas, es repartirlas en varios archivos (módulos) y usarlas con import. Por ejemplo: productos.py con la lógica de productos, main.py que la usa.

productos.py
def total_pedido(precio, cantidad, descuento=0):
    return precio * cantidad * (1 - descuento)
main.py
from productos import total_pedido    # traer la función de otro archivo
print(total_pedido(8500, 2, 0.25))    # 12750.0

Es lo mismo que importar math o json (capítulo 29), pero de tus propios archivos. Así, cada archivo se ocupa de una parte, y el programa no es un monstruo de mil líneas. Es justo cómo está organizado el backend de la tienda del librito 13 (db.py, pagos.py, stats.py, main.py).

El if __name__ == "__main__"

un patrón que vas a ver siempre
def main():
    print("el programa arranca acá")

if __name__ == "__main__":
    main()

Esa línea rara significa "ejecutá esto solo si este archivo se corre directamente, no si lo importan desde otro". Sirve para que un archivo pueda usarse como programa y como módulo importable sin que se ejecute de más. No hace falta entenderla a fondo ahora; reconocela, porque está en casi todos los programas Python.

Librerías: pip y entornos virtuales

  • pip instala librerías externas: pip install pandas (el track de Datos), pip install fastapi (los backends). Miles de librerías, para casi todo.
  • Entorno virtual: una "caja" aislada de librerías por proyecto, así las versiones de un proyecto no chocan con otro. Se crea con python -m venv venv y se activa. En proyectos serios, siempre.
  • requirements.txt: la lista de librerías que tu proyecto necesita, para que otro las instale de una (pip install -r requirements.txt). Lo viste en el librito de deploy.
Crecé cuando lo necesites

No arranques con módulos y entornos virtuales para un script de 20 líneas: sería sobreingeniería. Empezá simple, en un archivo. Cuando el programa crezca y se vuelva incómodo, ahí separás en funciones, después en archivos, después sumás un entorno virtual. La estructura sigue a la necesidad, no al revés. Pero saber que estas herramientas existen te dice hacia dónde crecer.

Proyecto: el juego de adivinar el número

Un clásico para practicar, y muy divertido de hacer. La computadora elige un número secreto del 1 al 100, y el jugador tiene que adivinarlo; en cada intento, el programa dice si es muy alto o muy bajo. Junta: azar (random), un bucle, condicionales, y contar intentos.

La receta

cómo lo pensás
1. Elegir un número secreto al azar (random)
2. Repetir (un bucle): pedir un intento
3. Comparar: ¿igual? ganó. ¿menor? "muy bajo". ¿mayor? "muy alto"
4. Contar los intentos
5. Cortar cuando acierta (break)
p_adivinar.py (versión probada, con intentos simulados)
import random
random.seed(3)                       # fijo para que la prueba sea reproducible
secreto = random.randint(1, 100)     # con esta semilla sale 31
intentos_simulados = [50, 25, 37, 31]  # simula lo que tipearía el jugador

intentos = 0
for intento in intentos_simulados:
    intentos += 1
    if intento == secreto:
        print(f"intento {intentos}: {intento} -> ACERTASTE en {intentos} intentos!")
        break
    elif intento < secreto:
        print(f"intento {intentos}: {intento} -> muy bajo, probá más alto")
    else:
        print(f"intento {intentos}: {intento} -> muy alto, probá más bajo")

La versión interactiva de verdad

Para probarlo lo simulamos con una lista de intentos (así la salida es reproducible). Para jugarlo de verdad, cambiás la lista por input dentro de un while:

        print(f"¡Acertaste en {intentos} intentos!")

    else:
        print("muy alto")
Fijate la estrategia del jugador

Los intentos simulados (50, 25, 37, 31) no son al azar: van partiendo el rango a la mitad cada vez. Es la "búsqueda binaria", la forma más rápida de adivinar: con 100 números, siempre ganás en 7 intentos o menos. Programar te entrena a pensar así, en estrategias eficientes. Cuando lo juegues, probá esa técnica.

Proyecto: una lista de tareas que se guarda

Una app de tareas (to-do) clásica, que junta casi todo: lista de diccionarios, funciones, y persistencia con JSON (para que las tareas sobrevivan al cerrar el programa). Es, en miniatura, cómo funciona cualquier app que guarda datos.

El diseño

Cada tarea es un diccionario {"texto": ..., "hecha": ...}. Todas viven en una lista. Funciones para agregar, completar y mostrar. Y al final, guardar en un archivo JSON (capítulo 46) para no perderlas.

p_todo.py
import json
tareas = []

def agregar(texto):
    tareas.append({"texto": texto, "hecha": False})

def completar(indice):
    tareas[indice]["hecha"] = True

def mostrar():
    for i, t in enumerate(tareas):
        marca = "[x]" if t["hecha"] else "[ ]"
        print(f"  {i}. {marca} {t['texto']}")

agregar("comprar harina")
agregar("preparar la masa")
agregar("hornear")
completar(0)
completar(1)
mostrar()

  1. [x] preparar la masa
  2. [ ] hornear
pendientes: 1

Guardar y recuperar (persistencia)

p_todo.py
# guardar la lista completa en un archivo JSON
with open("tareas.json", "w") as f:
    json.dump(tareas, f, ensure_ascii=False)

# volver a cargarla (por ejemplo, al abrir el programa de nuevo)
with open("tareas.json") as f:
    cargadas = json.load(f)
print("pendientes:", sum(1 for t in cargadas if not t["hecha"]))

Con json.dump guardás toda la lista en un archivo; con json.load la recuperás igualita. Así, si cerrás y volvés a abrir el programa, tus tareas siguen ahí. Ese sum(1 for t in cargadas if not t["hecha"]) cuenta las pendientes: es el patrón de contar (capítulo 14) en forma compacta.

Esto es una app, en esencia

Una lista de datos, funciones para modificarla (agregar, completar, borrar), y persistencia para que no se pierda: eso es el núcleo de casi cualquier aplicación. Cambiá el archivo JSON por una base de datos, y las funciones por endpoints de una API, y tenés una app web de verdad (libritos 10 y 13). Empezó como un ejercicio y es el esqueleto de todo.

Proyecto: analizar ventas desde datos

El proyecto final, y el más cercano a un problema real de negocio. Tomamos datos de ventas (como los que saldrían de un archivo o una base), y sacamos conclusiones: cuánto se facturó, cuántas unidades por producto, y cuál es el más vendido. Junta parseo de datos, diccionarios como acumuladores, y todo lo aprendido.

El código

p_ventas.py
ventas_texto = """Pizza,8500,2
Empanada,1200,12
Pizza,8500,1
Gaseosa,1800,5
Flan,3500,3
Empanada,1200,6"""

# 1. parsear el texto a una lista de diccionarios
ventas = []
for linea in ventas_texto.strip().split("\n"):
    nombre, precio, cant = linea.split(",")
    ventas.append({"producto": nombre, "precio": int(precio), "cantidad": int(cant)})

# 2. total facturado (acumular con una comprehension)
total = sum(v["precio"] * v["cantidad"] for v in ventas)
print(f"total facturado: ${total:,}")

# 3. unidades por producto (acumular en un diccionario)
por_producto = {}
for v in ventas:
    por_producto[v["producto"]] = por_producto.get(v["producto"], 0) + v["cantidad"]
print("unidades por producto:", por_producto)

# 4. el más vendido
mas_vendido = max(por_producto, key=por_producto.get)
print("más vendido:", mas_vendido, "con", por_producto[mas_vendido], "unidades")
